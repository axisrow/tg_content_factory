# TG Agent

**Зависимость для агентов кодирования: полный спектр действий с Telegram через CLI**

TG Agent — self-hosted инструмент автоматизации Telegram для агентов кодирования (Claude Code, OpenCode, Codex): агент действует в вашем Telegram (сообщения, каналы, админка, медиа) и ведёт контент-фабрику (сбор → генерация → модерация → публикация). Нативный путь — `tg-agent` CLI + скилл.

## Возможности

| Модуль | Описание |
|--------|----------|
| **tg-agent CLI** | ~250 команд на весь Telegram: чаты, каналы, сообщения, медиа, админка — каждая команда самодостаточна; демон не нужен, а при запущенном демоне команда работает на его подключении |
| **Скилл для агентов** | Каталог команд и safety-правила для агента — [`skills/tg-agent/SKILL.md`](https://github.com/axisrow/tg_content_factory/blob/main/skills/tg-agent/SKILL.md) |
| **Каналы** | Добавление, сбор, фильтрация сотен каналов |
| **Поиск** | FTS5 полнотекстовый + семантический поиск через векторные эмбеддинги |
| **Контент-пайплайны** | Генерация контента через LLM → модерация → авто-публикация |
| **Планировщик** | Периодический сбор, поисковые уведомления, расписание публикаций |
| **Фото-загрузчик** | Батчевая отправка фото, автоматическая очередь |
| **Аналитика** | Тренды, топ-сообщения, статистика каналов, контент-аналитика |
| **Dialogs** | Реальные действия в чатах: отправка, пересылка, редактирование, участники, админы |
| **Агент пайплайнов** | Движок контент-пайплайнов (бэкенды `deepagents` / `claude-agent-sdk`) с реестром агент-инструментов; встроенный агент-чат удалён в #1868 |

## Поверхности

**CLI + скилл для агентов кодирования — единственный интерфейс.** Новые возможности появляются в CLI и тестируются там; скилл описывает агенту каталог команд и правила безопасности:

```bash
tg-agent channel list
tg-agent search "запрос" --limit 20
tg-agent pipeline run 1
```

**Удалены в #1868:** веб-панель (`serve`), встроенный агент-чат с TUI и тредами (`agent …`) и MCP-сервер (`mcp-server`, вместе с агентными бэкендами Codex/ADK). Прежняя модель «пяти поверхностей» описана как история в [Карте сервисов](feature-map.md) и [Parity-матрице](parity-matrix.md).

## Демон и подключения

`tg-agent restart` запускает воркер-демон (сбор по расписанию, очереди, диспетчеры). Пока он работает, он владеет Telegram-подключением каждого аккаунта — одно подключение на аккаунт на машине, — а живые CLI-команды (`messages read --live`, все действия `dialogs`, `account info`, `search --mode telegram`, `pipeline run`, …) выполняются на этом подключении через локальный relay (127.0.0.1, токен в файле, доступном только владельцу): тот же вывод, без второго входа и без очереди. Без демона команда подключает аккаунт сама. В режиме gateway (`tg-agent global enable`) владелец подключений — общий gateway, и проекту не нужен свой ключ сессий. После обновления tg-agent перезапустите демон (`tg-agent restart`) и gateway (`tg-agent gateway restart --shared`) один раз: старый владелец отклоняется с этой подсказкой.
